## 1. Project Overview

**Quante** is an AI-native, white-label e-commerce builder SaaS. Users describe the store they want, the in-product AI (called "Quante", powered by the Claude API) generates a complete Next.js storefront, users iterate conversationally, and can then export the full source as a downloadable, deploy-ready ZIP or deploy it directly to Vercel with one click.

### Two completely separate surfaces

| Surface | Description | Design |
|---|---|---|
| **The Quante platform** | The builder/SaaS app users log into | Dark, technical, premium — Linear/Vercel aesthetic |
| **Generated storefronts** | White-label shops Quante produces | Brand-appropriate per brief, zero Quante branding |

**Critical non-negotiables:**
- White-label output — generated shops carry no Quante branding/telemetry
- Portable code — every export is a plain Next.js project running with `npm install && npm run dev`
- Manifest/code-gen driven — AI produces structured output that slots into a deterministic scaffold

### Tech Stack

**Platform:**
- Next.js 16.2.7 (App Router) + TypeScript 5
- Tailwind CSS v4 + `tw-animate-css` + `shadcn/ui`
- Framer Motion 12
- Clerk (auth — replaced Supabase Auth)
- Supabase (Postgres, RLS, Storage)
- Stripe (credit packs, Agency subscription, hosting subscription, managed store checkout; Stripe Connect routes removed 2026-09)
- Claude API (`@anthropic-ai/sdk 0.100.1`) — server-side only
- `jszip` for ZIP export
- `@vercel/sdk` for Vercel API

**Generated storefronts (scaffold):**
- Next.js 16.2.7 + TypeScript
- Tailwind CSS v4
- Framer Motion, lucide-react
- Cart state via React Context (localStorage-backed)
- CSS custom properties for theming (`--color-bg`, `--color-text`, etc.)
- No Stripe keys baked in — merchant provides their own via Vercel env vars or Quante managed payments

## 3. All API Routes

### Auth & ownership conventions (security audit 2026-09)

- **Auth** = Clerk `auth()` in each route; the platform has no Supabase-auth routes any more (`/auth/callback`, `/auth/signout` DELETED 2026-09). `proxy.ts` protects the app pages and rejects state-changing `/api/*` requests from a foreign Origin (CSRF guard; cross-site-by-design endpoints — Stripe webhook, `/api/webhooks/*`, `/api/store/*`, `/api/payments/*`, crons — are exempt and authenticate by signature/key/token).
- **Ownership** — every project-scoped route loads the project through `getOwnedProject(projectId, userId)` (`lib/auth/project.ts`) and answers **404** for "not found" and "not yours" alike. RLS does not protect anything server-side (service-role client).
- **Credits** — every paid route debits **before** the paid work via `debitCredits()` and refunds on failure via `refundDebit()` (`lib/credits.ts`, §9). `debitCredits` refuses accounts on `users.billing_hold` (402, `code: 'billing_hold'`).
- **Admin** routes use `requireAdmin()` (`lib/admin.ts`: verified primary email in `ADMIN_EMAILS`, fails closed).
- **Crons** use `isAuthorizedCron()` (`lib/cron-auth.ts`): `Authorization: Bearer $CRON_SECRET`, **401 when `CRON_SECRET` is unset**.
- **Store API** (called by deployed stores) authenticates with the per-project `QUANTE_API_KEY` as `Authorization: Bearer <key>`, looked up by SHA-256 hash + constant-time compare (`app/api/store/_lib/store-auth.ts`).

## 4. Database Tables

> All server-side code uses `supabaseAdmin` (service role), which bypasses RLS. RLS is a defence-in-depth layer only — ownership is enforced in code (`getOwnedProject`, `.eq('user_id', userId)`).
> Auth: Clerk JWT. RLS policies use `auth.jwt() ->> 'sub'` (not `auth.uid()`) since Clerk user_id is a text string, not a UUID.
> **Security migrations (2026-09):** `migration-credits-v2.sql` → `migration-security-foundation.sql` → `migration-security-{deploy-hosting-cron,generate,iterate-fix-section,projects-misc,qads,store-public,stripe-payments}.sql` → `migration-security2-{deploy-domains-misc,gen-pipeline,store-checkout}.sql` → `migration-security3-{hosting,quante-credits,store-api,webhook-secrets-qads}.sql` → `migration-security4-{identity-gate,mail-guards,misc}.sql`. **All 19 were applied to production on 2026-09-24** and verified (the files' own "NOT RUN" headers predate that). Most app paths fall back to weaker behaviour if a column/table is missing; the credit RPCs are mandatory.

### Core tables (schema.sql)

**`projects`**
```
id uuid PK
user_id text NOT NULL          -- Clerk user_id; soft-deleted rows become 'deleted:<owner>'
name text                      -- display name only — NEVER used to derive the subdomain or Vercel project
status text DEFAULT 'draft'    -- draft | published | archived | deleted (soft-delete tombstone, 2026-09; indexed)
vercel_project_id text          -- added by migration-hosting.sql; since 2026-09 always this project's own 'q-<uuid>' Vercel project
store_slug text UNIQUE          -- migration-security-foundation.sql: permanently claimed <slug>.<HOSTING_ROOT_DOMAIN> (getOrClaimStoreSlug); never re-derived; stays reserved on soft-delete
custom_domain text              -- migration-custom-domain.sql; UNIQUE on lower(custom_domain) (migration-security-deploy-hosting-cron.sql)
```

### RLS Summary

All tables have RLS enabled. Server-side code uses `supabaseAdmin` (service role) which bypasses RLS entirely, so RLS is defence-in-depth only and **every route must filter by the Clerk `userId` itself** (`getOwnedProject`). Pattern: `(auth.jwt() ->> 'sub') = user_id` for Clerk JWT; some older policies use `auth.uid()::text`.

2026-09 changes:
- The `schema.sql` policies **"service writes credit_ledger"** and **"service writes purchases"** (`INSERT … WITH CHECK (true)`, no `TO` clause → usable with the public anon key) were **dropped**, and INSERT/UPDATE/DELETE on `credit_ledger` and `purchases` revoked from `anon`/`authenticated` (verified in production: the anon key is denied on every credit RPC and on those inserts).
- `qads_generations_insert_own` dropped; writes on the Qads tables revoked from anon/authenticated.
- All new security tables: RLS on, **no policies** (most also revoke table privileges) → service role only.
- All credit / identity / trial / slot functions: `REVOKE ALL … FROM PUBLIC, anon, authenticated` + `GRANT EXECUTE … TO service_role`.

Fails closed if the file can't be analysed.

### Tiers
- **free/credit**: Credit-based. Rate limits: generate 5/hr, iterate 60/hr, section 15/hr. Project limit: 3.
- **agency**: No credit cost for iterate/fix. Project limit: 20. Spend bounded by `AGENCY_RATE_LIMIT_PER_MIN = 10` plus hourly/daily caps from the `quante_request_attempts` log. Agency perks (incl. free hosting) are off while `users.billing_hold` is set.

### Ledger mechanics (rewritten 2026-09 — `lib/credits.ts` + `migration-credits-v2.sql`)
- **Only `lib/credits.ts` writes the ledger**, through SECURITY DEFINER RPCs executable only by `service_role`: `debit_credits`, `grant_credits`, `grant_welcome_credits(_v2)`, `refund_debit`. Every RPC takes `pg_advisory_xact_lock(hashtext(user_id))` and computes `balance_after` inside the lock → concurrent requests are serialised per user (the old "read latest balance, insert snapshot − cost" minted credits and made N parallel generations cost 1).
- **Ordering:** current balance = `balance_after` of the highest `credit_ledger.seq` (monotonic, assigned at insert inside the lock). Never order by `created_at` (= transaction start time, can be out of write order).
- **Debit before work:** every paid route calls `debitCredits(userId, cost, reason, ref)` first (a single atomic balance check + debit) and `refundDebit(userId, ref, reason, refundReason)` on failure. `generate` debits at POST, not after the job.
- **Refund caps:** `refund_debit` never refunds more than was debited under that ref minus every earlier positive row with that ref (grants excluded), so repeated/concurrent refunds are safe. Refunds for failures a user can provoke (model output unusable, a build that never passes auto-fix) go through `refundCapped()` — max `DAILY_CAPPED_REFUND_LIMIT = 5` per user per 24h, recorded in `credit_refund_claims`. `/api/credits/refund` only refunds a version whose auto-fix loop is provably exhausted (§3).
- **`users.billing_hold`:** set by the Stripe webhook on chargebacks or when a clawback leaves a shortfall (`purchases.clawback_shortfall`). While set, `debitCredits` returns `billing_hold` (402), Agency perks and intake/fix are refused. Cleared only when no `billing_disputes` row for the user is open/lost.
- **Welcome grant** (`ensureWelcomeGrant`, `app/api/credits/welcome-grant.ts`; called from `/api/credits/balance`, dashboard and billing pages): only once the account has a VERIFIED primary email or phone; disposable-email domains need a verified phone; once per PERSON — verified emails/phones are normalized (lower-case, `+tag` stripped, Gmail dots removed, googlemail→gmail, E.164 phones), SHA-256 hashed and checked by `grant_welcome_credits_v2` against `welcome_grants` (refusal `identity_already_used`); identities recorded in `user_identities` (also used for the one-per-person hosting trial). Accounts with earlier ledger rows get a one-time identity backfill (`record_user_identities`).
- **Chargebacks / refunds of packs:** webhook claws back as much as the balance allows via `debitCredits(..., 'purchase_refund' | 'chargeback', purchase.id, { ignoreBillingHold: true })`, tracks `purchases.refunded_credits / chargeback_credits / clawback_shortfall`, and on a won dispute returns the slice with `refundDebit(..., 'chargeback', 'chargeback_reversed')`.

### Credit packs (Stripe)
- `starter` 50 cr = $9.99
- `builder` 150 cr = $24.99 (popular)
- `studio` 500 cr = $69.99
- Stripe checkout uses `currency: 'usd'` and `pack.priceCents`; `metadata.type = 'credits'`

## 11. Vercel Integration (`lib/hosting/vercel.ts`)

Raw REST calls to `api.vercel.com` (`vercelApiFetch`, since 2026-08-19 — `@vercel/sdk` response validation broke) with `VERCEL_TOKEN` (throws when missing) + `VERCEL_TEAM_ID`. All store projects live in Quante's shared Vercel team, so identity must never come from anything user- or AI-controlled.

### `ensureProjectVercel(projectId)` — replaces `ensureVercelProject(slug)` (DELETED 2026-09)
The old function looked up a Vercel project **by store name** in the shared team: naming your store like someone else's deployed your code onto their project, subdomain, custom domain and env (audit critical #0). Now:
1. Read `projects.vercel_project_id`; if that Vercel project still exists → harden settings (lazy PATCH) + disable deployment protection → return it.
2. Otherwise create `q-<project uuid without dashes>` (a 409 from a concurrent first deploy → look it up by that name — only this project can derive it) with `framework: 'nextjs'`, `installCommand: 'npm install --ignore-scripts'`, `buildCommand: 'next build'`, `oidcTokenConfig: { enabled: false }`; PATCH `ssoProtection: null`.
3. Persist with compare-and-set (`.is('vercel_project_id', null)` or `.eq(stale id)`) and re-read — concurrent first deploys agree on one id.
Legacy rows sharing one Vercel project are logged as `SECURITY: … shared by Quante projects` for manual migration (queries in `migration-security-foundation.sql`). Callers must have checked ownership (`getOwnedProject`).

### `getOrClaimStoreSlug(projectId, desiredName)`
The public `<slug>.<HOSTING_ROOT_DOMAIN>` host is `projects.store_slug`, claimed once and never re-derived (renaming the project or the AI changing the brand can't move or collide it). Candidates `toStoreSlug(name)` (≤ 50 chars) → `-2` … `-30` → `-<8 hex of uuid>`; DNS-label regex, reserved names refused, slugs owned by another project or still on another project's deployment skipped; UNIQUE index + 23505 retry.

### `setEnvVars(vercelProjectId, vars, { encrypted? })`
Throws for any key outside `QUANTE_API_URL | QUANTE_PROJECT_ID | QUANTE_API_KEY | NEXT_PUBLIC_*` — platform secrets can never reach AI-authored store code.

### `createPreviewDeployment(vercelProjectId, files, storeSlug?)`
Production-target auto-deploy. With a valid `storeSlug` it calls `attachDomain(vercelProjectId, <slug>.HOSTING_ROOT_DOMAIN)` and returns the subdomain URL **only if the attach succeeded**; an attach error (the host belongs to another project) now falls back to the raw deployment URL (it used to be swallowed and the subdomain reported anyway). Used by `autoDeployCodeVersion` / redeploy only when the store is `everLive` and the hosting gate allows production.

### `createVercelPreviewDeploy(vercelProjectId, files, name?)`
True Vercel preview (no `target`, no subdomain). Used after generate, for paid previews (2 cr) and for iterate/fix/redeploy of stores that may not deploy to production.

### `createDeployment(vercelProjectId, files, { target: 'production', projectSlug? })`
Push to Live. Domain assigned later via `attachDomain` in the GET `/api/deploy` handler. Every deployment POST also carries `projectSettings` (the pinned build settings above).

### `streamDeploymentLogs(deploymentId, onEvent, signal?)`
Calls Vercel events API (`/v2/deployments/{id}/events?direction=forward&follow=1`). Parses NDJSON. Emits events via callback. Detects `readyState === 'READY'` or `'ERROR'` in payload to emit terminal events and return.

### `getDeploymentStatus(deploymentId)`
Maps Vercel `readyState` → `'queued' | 'building' | 'ready' | 'error' | 'canceled'`.

### `getBuildError(deploymentId)`
Fetches last 20 stderr lines from Vercel events API.

### `attachDomain(vercelProjectId, domain)`
Calls Vercel add-domain API. Returns `{ verified: boolean, dnsInstructions? }`. On an error it checks whether the domain is already on THIS project (then success); otherwise it **throws** — a 409 "domain in use" by another project is no longer treated as success.

### `getDomainDnsConfigured(domain)`
`GET /v6/domains/{domain}/config` → `true` only when public DNS really points at Vercel (`misconfigured === false`); `null` when unknown. Used for custom-domain proof (the `verified` flag from `attachDomain` proves nothing inside Quante's own team).

## 12. Known Bugs / Gotchas

### maxDuration Limits (Vercel)
- `/api/quante/generate`: `maxDuration = 300` (Vercel Pro hard cap; Enterprise allows up to 800 but the project is not on Enterprise as of 2026-08-12). Uses `claude-opus-4-7` at `MAX_TOKENS=128000` (model ceiling). A **soft abort** fires at 270s: the Claude stream is killed and the route attempts to use whatever files were generated so far (requires the 4 core files: `data/products.ts`, `data/config.ts`, `styles/store.css`, `components/store/HomePage.tsx`). Since Level 3 (2026-08-11), the entire generation runs inside `Next.js after()` — the HTTP handler returns 202 immediately and the client polls `/api/quante/generate/status` for progress; there is no long-lived stream that could idle-drop, so the old 15s keepalive ping is gone. The client-side `isJobStuck` circuit breaker in `lib/generation-poll.ts` treats a job still `running` past 400s as terminal.
- `/api/quante/iterate`: `maxDuration = 300`. With large stores (many files), sending all files as context can be slow.
- `/api/deploy/logs`: `maxDuration = 300`. Build logs stream for the duration of the Vercel build (~2-3 min typically).

### RLS auth.uid() vs auth.jwt() ->> 'sub'
The project switched from Supabase Auth to Clerk. Old policies used `auth.uid()`. New policies must use `(auth.jwt() ->> 'sub')`. Some migrations still use `auth.uid()::text` in store-related policies (store_orders, store_earnings, etc.) — this works because Supabase maps the JWT `sub` to `auth.uid()` when a JWT is set. However, when `supabaseAdmin` (service role) is used, RLS is bypassed entirely. Be careful if any code uses the anon-key client — the JWT needs to be a valid Clerk JWT passed as the auth header.

### supabase/server.ts Re-exports Admin Client — ownership is YOUR job
`createClient()` in `lib/supabase/server.ts` just returns `supabaseAdmin`. There is NO per-request cookie-based client (the unused `lib/supabase/client.ts` / `middleware.ts` were deleted 2026-09). All queries run as service role (RLS bypassed), so every project-scoped route must load the project with `getOwnedProject(projectId, userId)` (`lib/auth/project.ts`) or an explicit `.eq('user_id', userId)` and answer 404 for "not yours". The 2026-09 audit found IDORs exactly where this was missing (generate `projectId`, generate/status, section, domains/connect, deploy logs, preview/component).

### Credits: ONLY through `lib/credits.ts` (2026-09)
Never `insert` into `credit_ledger`, never compute `balance_after` in app code, never read the balance ordered by `created_at`. Use `debitCredits` (before the work) / `refundDebit` (on failure; ref-capped) / `grantCredits` (idempotent per ref) / `getBalance` (by `seq`). The RPCs are executable by `service_role` only and serialise per user. Pick a fresh `randomUUID()` ref per paid request (or a meaningful id like the job/version/export id) and refund with the same ref + debit reason. Refunds for user-provokable failures go through `refundCapped()` (5/day). A new paid route must also handle `error: 'billing_hold'` (402).

### Never derive a store's identity from its name (2026-09)
The Vercel project comes from `ensureProjectVercel(projectId)` and the subdomain from `getOrClaimStoreSlug(projectId, name)` (`projects.store_slug`). Never call Vercel's project lookup by store name, never build `<toStoreSlug(project.name)>.<HOSTING_ROOT_DOMAIN>` for anything security-relevant, and never treat an `attachDomain` error as success. Legacy projects that shared a Vercel project must be split manually (queries in `migration-security-foundation.sql`).

### AI-written store files are filtered (2026-09)
Generate/iterate/fix save only files that pass `filterAiStoreFiles()`; `buildStoreFiles` re-applies `rejectAiStoreFile()` and forces LOCKED scaffold files. Consequences: the AI cannot add route handlers (`app/api/**`, `route.ts`), middleware, `package.json`/`vercel.json`/config changes, server actions, Node imports, external `fetch`, or read server env (`process.env` beyond `NEXT_PUBLIC_*`/`NODE_ENV`). Copy text inside strings/JSX may contain words like "global"/"Function" (an intermediate version wrongly dropped such files — regression tests in `__tests__/store-file-filter.test.mjs`). If you change the rules, update `AI_FILTER_PROMPT_NOTE` (`lib/generation-checkpoint.ts`) too. A dropped core file fails a generation (refunded).

### Hosting gate & trial (replaces "Deploy Credits Timing")
Production deploys cost 0 credits and are gated by `getHostingGate()`; the 30-day trial is claimed and stamped in **POST** `/api/deploy` (not when the client polls), once per user and per identity-linked group (`hosting_trials`, `claim_hosting_trial_v2`), and released if the first live build fails. Auto-deploys (iterate/fix/redeploy/restore) go to production only when the store is already `everLive` AND the gate allows it — otherwise a true preview, so chat edits can't replace a suspended store's maintenance page or keep a store live for free. Accounts with no verified email/phone get no free trial once the identity migration is in.

### `STORE_CHECKOUT_REQUIRE_KEY`
`/api/store/checkout` identifies the project by the store's `QUANTE_API_KEY` (sent server-side by the scaffold's locked checkout proxy). Stores deployed before that proxy existed still check out through logged keyless paths (`[store/checkout] keyless legacy checkout`) matched by Origin/Referer against the project's own origins. After every hosted store has been redeployed and those log lines stop, set `STORE_CHECKOUT_REQUIRE_KEY=true` to switch the keyless paths off (note: a keyed store is treated as keyless while its IP sits in the store-key failure throttle and its key was never verified on that instance).

### Fail-closed env vars
Without `CRON_SECRET` every cron returns 401 (`lib/cron-auth.ts`). Without an https `NEXT_PUBLIC_APP_URL` Push to Live returns 503, hosting-subscribe/domain-purchase Stripe redirects are refused and absolute invoice/webhook URLs are not built (the old `https://quante.vercel.app` fallbacks were removed). Without `INVOICE_LINK_SECRET` invoice link tokens are neither minted nor accepted. Empty `ADMIN_EMAILS` = no admins; `/api/admin/grant-credits` additionally needs `ADMIN_SECRET`.

### CSRF / Origin guard in `proxy.ts`
State-changing `/api/*` requests whose `Origin`/`Sec-Fetch-Site` is not the platform are rejected with 403 (generated stores live on the same site `*.stores.quantecode.com`, so Clerk's SameSite=Lax cookie would otherwise ride along). A new endpoint that is legitimately called cross-site (webhook, gateway callback, store API) must be added to `isCrossSiteApi` and authenticate by signature/key/token.

### Sandbox payments are `test_paid`
While `project_secrets.payment_test_mode` is true (still true on many pre-2026-09 rows; default is now false), Comgate/GoPay/PayPal payments only set `payment_status='test_paid'` — never `paid` — and send no "payment received" mails; such orders can't be shipped through the guarded carrier routes. There is no fallback to Quante's own gateway accounts any more.

### Migration file headers say "NOT RUN"
The 19 security migrations (see §4) were written before they were applied; their headers still say "NOT RUN AGAINST PRODUCTION", but all were applied and verified on 2026-09-24. Most app paths degrade gracefully if a column/table is missing (logged fallbacks), but the credit RPCs are mandatory.

### Lucide Icon Names
`lucide-react ^1.17.0` has a different icon set than v0.x. Social icons (Instagram, Twitter, etc.) do not exist. `sanitizeLucideImports()` in `build.ts` replaces them automatically. Always check SYSTEM_PROMPT_CODE_GENERATION for the current allowlist.

### Middle Dot in Footer (Unicode Turbopack Issue)
Previous bug: a middle dot character (·) in the Footer template caused Turbopack to fail. Fixed by replacing with a dash (-). See commit `469e589`.

### Code Versions vs Manifest Versions
The project has TWO generation approaches:
- **Legacy (manifest)**: Claude generates a `ShopManifest` JSON → renderer maps it to components. Uses `manifest_versions` table. Still used for the preview iframe in `app/(preview)/`.
- **Current (code-gen)**: Claude generates actual TypeScript/React files. Uses `code_versions` table. Used by all new generate/iterate/fix/deploy/export routes.

Export route (`/api/export`) checks `code_versions` first, falls back to `manifest_versions`.

### Token Limits
`AGENCY_TOKEN_CAP = 64_000` for agency users. Free users also use 64,000 in iterate. **Generation uses 128,000** (`MAX_TOKENS` in `app/api/quante/generate/route.ts`, set to the `claude-opus-4-7` output ceiling). These are `max_tokens` values — the actual response may be shorter. If output is truncated (no closing `</file>` tag), parsing fails and returns error, but Level 3 checkpointing preserves partially-parsed files so a resumed poll can still see what got through.

### Agency Project Archiving
On Agency plan cancellation webhook, projects beyond the free limit (3) are set to `status='archived'`. They're hidden but not deleted. User sees a warning to reactivate. If they upgrade again, archives are NOT automatically restored — they need to be unarchived manually.

### Stripe webhook: `type` metadata
The Stripe webhook (`/api/stripe/webhook`) distinguishes checkout sessions by `session.metadata.type`:
- `type = 'credits'` (or legacy: missing) = credit pack purchase — credits come from the server-side pack table by amount paid, never from `metadata.credits`; any other unknown type is ignored
- `type = 'store_sale'` = deployed store checkout
- `type = 'hosting'` / `'agency'` = no-op here (the `customer.subscription.*` events handle them)
- `type = 'domain_purchase'` = domain registration flow
Refunds/disputes arrive as `charge.refunded` / `charge.dispute.*`; `account.updated` (Connect) is ignored. Required dashboard events are listed in `docs/TODO.md`.

### Preview URL — always use storeUrl, never raw vercel.app URLs
Raw Vercel deployment URLs (e.g. `axiom-az20nza2a-mikelfxs-project.vercel.app`) are blocked in iframes by Vercel's security headers. The canonical `storeUrl` (computed server-side) is ALWAYS used instead. The `resolveUrl()` helper in StudioClient swaps any `vercel.app` URL for `storeUrl` at every `setPreviewUrl()` call site.

### Preview vs production deployment distinction
In `deployments` table: iterate/fix/auto-deploys have `domain = null`. Live (production) deploys from `/api/deploy` have `domain = '<store_slug>.stores.quantecode.com'` (cleared again if the domain attach fails). StudioClient uses `!!d.domain` (`isLiveDeploy`) to distinguish:
- Live deploy building → shows Deploy tab loading card, polls `GET /api/deploy?id=...` every 12s
- Auto-deploy building → polls status once on page load (to avoid SSE triggering auto-fix for stale errors), then starts `startLogStreaming` only if genuinely still building
- Live deploy ready → updates `deployStatus`, `deployUrl`, `deployDomain`
- Auto-deploy ready → updates `previewUrl = storeUrl`, `previewReady = true`

### SSE log streaming — termination guarantee
`streamDeploymentLogs` can return without emitting a terminal event (build was already complete when streaming started). `GET /api/deploy/logs` handles this in two layers:

1. **Post-stream check (normal path)**: After `streamDeploymentLogs` returns, if no terminal event was emitted, it calls `getDeploymentStatus` and sends appropriate `stream_end` + closes the SSE controller.
2. **Catch block polling (hang timeout path — fixed 2026-07)**: The 90-second hang timeout (`abortController.abort()`) causes the Vercel events SSE to throw AbortError. The catch block now polls `getDeploymentStatus` every 10s for up to 5 minutes (30 iterations), emits `build_error`/`stream_end` when the status resolves, then closes. Without this fix, the catch block would early-return after silently closing — leaving the client stuck on "Building on Vercel…" forever for builds that errored before the stream opened.

```ts
// Key variables: terminalEventEmitted (bool), resolved (bool, scoped to catch block)
// sendEvent({ type: 'build_error', message }) + sendEvent({ type: 'stream_end', state: 'error' })
// sendEvent({ type: 'stream_end', state: 'ready' })
```

This prevents the client from hanging indefinitely on "Building on Vercel…" in all cases.

### First-time generate requires Push to Live
After `POST /api/quante/generate`, the client sets `showPushToLive = true` instead of starting log streaming. The auto-deploy (a true Vercel preview, no subdomain) runs in the background but the client shows a "Push to Live" button (0 credits; hosting-gated). The user must click it to trigger a proper production deploy that attaches the subdomain. Iterate/fix auto-deploys (not first generation) still use the existing log streaming + `previewReady` flow.

### In Progress / Known Issues
- **Preview iframe**: For code-gen stores, the preview is the `storeUrl` domain URL (e.g. `https://axiom.stores.quantecode.com`) loaded in an iframe. The legacy `/preview/[id]/...` routes inside the platform exist for legacy manifest-based stores but code-gen stores bypass them. The iframe content equals what's live at the domain — not a separate "staging" view.
- **maxDuration on Vercel**: 300s routes are at the Vercel max for Pro plans. Long briefs with claude-opus-4-7 can approach this. Since Level 3 (2026-08-11), graceful resume DOES exist for `/api/quante/generate`: background job via `after()`, checkpoints every 4s to `generation_jobs`, client polls `/api/quante/generate/status`, and `/new/page.tsx` shows a resume banner on reload if a `pending-generation` localStorage marker survives. `StudioClient.tsx` was synced to the same 202+polling contract on 2026-08-12 (previously broke first-time chat generations with "Stream ended unexpectedly."). Iteration and other routes still use their original NDJSON streams.
- **RLS inconsistency**: Some older migration policies use `auth.uid()::text` instead of `(auth.jwt() ->> 'sub')`. This works because Supabase maps the JWT sub claim to uid, but if the JWT structure changes it could break. All server code uses service-role client anyway.
- **Admin panel feature flag**: `adminPanel?: boolean` exists in ShopManifest but the admin panel in the Studio is always available (not gated by the flag in the current UI).
- **Auto-deploy on first generate**: since 2026-08-07 the generate route creates a true Vercel preview (`createVercelPreviewDeploy`, no subdomain) — a validation build, not a production deploy; the production deploy happens on "Push to Live".
- **Stale pricing copy**: some UI/marketing/Terms text still says "Push to Live 5 cr", "ZIP 5 cr", EUR prices or "credits only on success" — tracked in `docs/TODO.md` (not a code-path issue: `CREDIT_COSTS` is authoritative).
- **Unverified against live Vercel**: store project hardening (`npm install --ignore-scripts`, `oidcTokenConfig.enabled=false`, `ssoProtection: null`) — confirm with one real store deploy.
